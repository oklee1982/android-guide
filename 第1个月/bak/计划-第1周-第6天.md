第 2-5 小时：功能整合

目标：形成可用 Demo。

建议分步骤：

1. 页面结构与导航

- MainActivity：展示列表、入口按钮、搜索/筛选占位。
- SecondActivity：兼具新增/编辑功能（根据 intent 中是否传入 User 决定）。
- Detail 页面：可复用 SecondActivity 或新建 `DetailActivity`，展示用户信息并提供删除按钮。

2. 新增/编辑流程

- 在 MainActivity 点击“新增” → SecondActivity（空表单）。
- 在列表 item 点击 → SecondActivity 进入“编辑模式”，显示现有数据并允许修改。
- 保存后通过 Activity Result 将修改后的 User 返回主界面，并更新列表。

3. 删除流程

- Detail 页或长按列表项进行删除确认。
- 删除后刷新列表并显示 Toast。

4. 日志与错误提示

- 引入简单的日志封装：

```kotlin
object AppLogger {
    private const val TAG = "UserDemo"

    fun d(message: String) = Log.d(TAG, message)
    fun e(message: String, throwable: Throwable? = null) = Log.e(TAG, message, throwable)
}
```

- 在关键节点打印日志（新增、编辑、删除、Activity Result 回调）。
- 将错误提示统一方法：

```kotlin
fun Context.showToast(message: String) {
    Toast.makeText(this, message, Toast.LENGTH_SHORT).show()
}
```

5. 统一状态管理（可选）

- 使用 `sealed class UiState` 表示加载/成功/空态/错误，MainActivity 根据状态显示视图。
- 或使用简单枚举记录当前模式（新增 / 编辑）。

6. 列表排序与搜索（可设占位）

- 至少支持按照姓名排序，搜索可作为后续任务。

7. 验收检查

- 横竖屏切换后是否保留输入数据（如未实现，记录在问题清单）。
- 删除后返回列表，数据是否同步。
- 日志是否记录关键行为。
